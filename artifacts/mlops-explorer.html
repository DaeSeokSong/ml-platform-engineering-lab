Feast: 예측 시점에 알 수 있었던 값만 고르기

예시 피처는 사용자의 학력이에요. 원본 Adult 실습의 실제 변화 이력이 아닌 설명용 가상 이력입니다.

  1. 09:00 · HS-grad
  2. 10:00 · Bachelors
  3. 11:00 · Masters

실습에서는 어떻게 적용했나요?

실제 실습에서는 사용자 ID와 기준 시각으로 Parquet 또는 S3에서 과거 피처를 조회했어요. 온라인 조회는 materialization으로 Redis에 적재한 뒤 값을 가져왔고, 이번 배치 추론은 과거 조회를 사용했어요.

KFP: 출력이 준비돼야 다음 작업이 시작돼요

한 실행의 S3 경로를 출력 파라미터로 넘겨 세 작업을 연결했어요. 파일 자체는 S3에 있고 KFP는 실행 순서를 관리합니다.

실제로 확인한 결과

사용자가 실행한 통합 Run의 상태가 SUCCEEDED였어요. 모델 파일 8개의 SHA-256 검사, Pod의 모델 로드·Feast 조회는 별도로 확인했고, 새로운 PC 전체 설치 검증과는 구분해 기록했어요.

VersityGW의 파일과 S3는 어떻게 연결됐나요?

전용 테스트 폴더에서 먼저 만든 파일을 S3로 읽었고, S3로 올린 JSON이 실제 디렉터리에 생겨 같은 내용인지 확인했어요. 개인 파일 서버나 기존 업무 파일은 사용하지 않았어요.
